# 备份与恢复指南

> 面向用户的使用说明。技术原理见 [dev-guide/security.md](../dev-guide/security.md)；服务端主密钥说明见 [master-key.md](master-key.md)。

## 1. 为什么需要备份

量潮机密云采用**服务端加密**设计：你的机密内容由服务端主密钥（MASTER_KEY）加密落盘，
登录后即可正常使用。备份的意义：

1. **主密钥丢失时唯一恢复通道**——密钥丢失后密文无法解密，只能靠备份恢复（见 [master-key.md](master-key.md)）
2. **误删/误操作保险**——虽然 OSS 开启版本控制可回滚，但离线备份更稳妥
3. **服务故障兜底**——极端情况下数据桶不可用时，备份可重建

## 2. 备份什么：全部条目的明文导出

进入 **备份与恢复** 页，点击 **「导出备份（明文 NDJSON）」**：

```
导出内容 = 全部条目（名称 + 密码明文），NDJSON 格式
```

- 导出的备份是**明文副本**（客户端与服务端交互的就是明文，服务端负责加密落盘）
- 点击导出后内容复制到剪贴板，**请保存为文件**（如 `qtcloud-secret-backup.ndjson`）并妥善保管

## 3. 如何保存备份

备份是明文，保存要求比旧方案（密文信封）更高：

| 方式 | 推荐度 | 说明 |
|------|--------|------|
| **加密压缩包 + 密码，存入另一处** | ⭐ 最推荐 | 如 7z/zip 加密后放网盘/移动硬盘，密码单独保管 |
| **存入另一个密码管理器** | 推荐 | 鸡蛋放另一个篮子，注意两个服务不能同时不可用 |
| 明文直接存放 | 不推荐 | 备份即明文，存放介质泄露 = 数据泄露 |

建议**定期**（如每月）导出一次，保持备份接近最新。

## 4. 如何恢复

1. 登录客户端 → 备份与恢复页
2. 粘贴备份内容（NDJSON）到文本框
3. 点击 **「从备份恢复」**——逐条上传合并（按 id 幂等覆盖）

恢复成功后，列表中应能看到备份中的全部条目。

## 5. 主密钥（MASTER_KEY）丢失怎么办

见 [master-key.md](master-key.md)「丢失后的处置流程」：生成新密钥 → 重新部署 →
清空数据 → **用本页的备份恢复**。

**结论**：请把「导出明文备份」纳入例行操作——它是主密钥丢失时唯一的恢复通道。
